📡 ESTRUCTURA DE BASE DE DATOS

TABLA PERSONA (creada automáticamente)
  idPersona .............. INTEGER PRIMARY KEY AUTO_INCREMENT
  nombre ................. VARCHAR(200) ⭐
  correo ................. VARCHAR(150) NULLABLE
  cargo .................. VARCHAR(150) NULLABLE
  institucion ............ VARCHAR(200) NULLABLE
  tipo ................... ENUM('INTERNO','EXTERNO')
  activo ................. BOOLEAN DEFAULT TRUE

TABLA CORRESPONDENCIA (creada con documento)
  idDocumento ............ INTEGER PRIMARY KEY AUTO_INCREMENT
  cite ................... VARCHAR(100) ⭐
  asunto ................. TEXT ⭐
  fecha .................. DATETIME AUTO_CURRENT ⏰
  idTipoDocumento ........ INTEGER FK → TIPO_DOCUMENTO
  idEstado ............... INTEGER FK → ESTADO_DOCUMENTO (="Recibido")
  idUrgencia ............. INTEGER FK → NIVEL_URGENCIA
  idRemitente ............ INTEGER FK → PERSONA.idPersona
  activo ................. BOOLEAN DEFAULT TRUE

TABLA CORRESPONDENCIA_DESTINATARIO (múltiples)
  id ..................... INTEGER PRIMARY KEY AUTO_INCREMENT
  idDocumento ............ INTEGER FK → CORRESPONDENCIA
  idPersona .............. INTEGER FK → PERSONA
  activo ................. BOOLEAN DEFAULT TRUE

CATÁLOGOS (datos preexistentes vía seeders)
  TIPO_DOCUMENTO ......... 6 tipos predefinidos
  NIVEL_URGENCIA ......... 4 niveles predefinidos
  ESTADO_DOCUMENTO ....... "Recibido", "Derivado", "Finalizado", "Archivado"
  DEPARTAMENTO ........... 6 departamentos predefinidos

⚡ CARACTERÍSTICAS ESPECIALES

✨ CREACIÓN AUTOMÁTICA DE REMITENTE
   └─ No requiere estar registrado previamente
   └─ Se crea automáticamente en PERSONA
   └─ Se asigna como remitente del documento

✨ MÚLTIPLES DESTINATARIOS
   └─ Selecciona 1 o más departamentos
   └─ Se crean N registros en CORRESPONDENCIA_DESTINATARIO
   └─ Contador dinámico en tiempo real (sin refresh)

✨ ESTADO AUTOMÁTICO
   └─ Siempre comienza en "Recibido"
   └─ No es editable por el usuario
   └─ Configurable desde la BD

✨ FECHA AUTOMÁTICA
   └─ Se asigna timestamp actual al guardar
   └─ DATETIME CURRENT_TIMESTAMP en BD

✨ MODULARIDAD TOTAL
   └─ NO afecta módulos: Enviadas, Recibidas, Dashboard
   └─ Cada ruta completamente independiente
   └─ Puedes desarrollar otros módulos en paralelo

📝 EJEMPLO COMPLETO DE USO

ESCENARIO: Registrar solicitud de una universidad externa

DATOS INGRESADOS:
  CITE: SGPA-2026-05-0421
  Asunto: Solicitud de inscripción a maestría en Defensa
  Tipo Documento: Oficio
  Nivel Urgencia: Normal
  Nombre Remitente: Lic. María García López
  Correo: maria.garcia@univ.edu.bo
  Cargo: Directora de Admisiones
  Institución: Universidad Mayor de San Andrés
  Tipo Remitente: EXTERNO
  Departamentos: ✓ Dirección General, ✓ Secretaría

SISTEMA EJECUTA (transacción):

  1️⃣ INSERT INTO PERSONA
     VALUES (NULL, 'Lic. María García López', 'maria.garcia@univ.edu.bo',
             'Directora de Admisiones', 'Universidad Mayor de San Andrés',
             'EXTERNO', true);
     → idPersona = 1

  2️⃣ INSERT INTO CORRESPONDENCIA
     VALUES (NULL, 'SGPA-2026-05-0421',
             'Solicitud de inscripción a maestría en Defensa',
             NOW(), 2, 1, 1, 1, true);
     → idDocumento = 1

  3️⃣ INSERT INTO CORRESPONDENCIA_DESTINATARIO
     VALUES (NULL, 1, 2, true),   -- Documento 1 → Dirección General (id=2)
            (NULL, 1, 3, true);   -- Documento 1 → Secretaría (id=3)

USUARIO VE:
  ✅ "¡Éxito! Documento registrado correctamente"
  ✅ Formulario se limpia completamente
  ✅ Contador de departamentos vuelve a 0
  ✅ Listo para registrar siguiente documento
